# Тест-кейсы

## AUTH-01 — Модуль создания пользователя

### TC-01-AUTH-01-FAIL-VERY_LONG_LOGIN-OTHERS_CORRECT

- **Тип:** FAIL (негативный)
- **Проверка:** Валидация поля «логин»
- **Входные данные:** логин — очень длинный; email, пароль, подтверждение пароля — корректные
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение об ошибке валидации логина; регистрация не выполняется

### TC-02-AUTH-01-FAIL-VERY_LONG_PASSWORD-PASSWORDS_DIFFER-OTHERS_CORRECT

- **Тип:** FAIL (негативный)
- **Проверка:** Валидация поля «пароль» и проверка совпадения паролей
- **Входные данные:** пароль — очень длинный; подтверждение пароля — не совпадает с паролем; логин, email — корректные
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение об ошибке валидации пароля и/или несовпадения паролей; регистрация не выполняется

### TC-03-AUTH-01-FAIL-EMPTY_LOGIN_OTHERS_CORRECT

- **Тип:** FAIL (негативный)
- **Проверка:** Обязательность поля «логин»
- **Входные данные:** логин — пустой; email, пароль, подтверждение пароля — корректные
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение об ошибке обязательности логина; регистрация не выполняется

### TC-04-AUTH-01-FAIL-VERY_LONG_EMAIL_CORRECT_FORM-OTHERS_CORRECT

- **Тип:** FAIL (негативный)
- **Проверка:** Валидация поля «email» (длина при корректном формате)
- **Входные данные:** email — очень длинный, но корректного формата; логин, пароль, подтверждение пароля — корректные
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение об ошибке валидации email; регистрация не выполняется

### TC-05-AUTH-01-FAIL-INCORRECT_EMAIL-OTHERS_CORRECT

- **Тип:** FAIL (негативный)
- **Проверка:** Валидация формата поля «email»
- **Входные данные:** email — некорректного формата; логин, пароль, подтверждение пароля — корректные
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение об ошибке некорректного email; регистрация не выполняется

### TC-06-AUTH-01-FAIL-EMAIL_EXISTS_OTHERS_CORRECT

- **Тип:** FAIL (негативный)
- **Проверка:** Уникальность поля «email»
- **Входные данные:** email — уже зарегистрированный в системе; логин, пароль, подтверждение пароля — корректные
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение об ошибке занятого email; регистрация не выполняется

### TC-07-AUTH-01-FAIL-LOGIN_EXISTS_OTHERS_CORRECT

- **Тип:** FAIL (негативный)
- **Проверка:** Уникальность поля «логин»
- **Входные данные:** логин — уже занятый в системе; email, пароль, подтверждение пароля — корректные
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение об ошибке занятого логина; регистрация не выполняется

### TC-08-AUTH-01-SUCCESS_ALL_CORRECT

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Успешная регистрация при корректных данных
- **Входные данные:** логин, email, пароль, подтверждение пароля — корректные и валидные
- **Ожидаемый результат:** пользователь успешно создан; переход на форму входа

## PROJ-02 — Модуль по работе со списком проектов

### TC-01-PROJ-02-SUCCESS_ONLY_MEMBER_PROJECTS_VISIBLE

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Отображение только проектов, в которых состоит пользователь
- **Входные данные:** пользователь состоит в нескольких проектах и не состоит в других проектах
- **Ожидаемый результат:** на главной странице отображаются только проекты, в которых состоит пользователь; проекты без участия пользователя не отображаются

### TC-02-PROJ-02-SUCCESS_PROJECT_CARD_CLICKABLE

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Кликабельность карточки проекта
- **Входные данные:** пользователь состоит в проекте; проект отображается в списке
- **Ожидаемый результат:** каждый проект представлен кликабельной карточкой

### TC-03-PROJ-02-SUCCESS_CARD_SHOWS_TITLE_AND_OPEN_BUGS_COUNT

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Отображение названия и количества открытых багов на карточке
- **Входные данные:** проект имеет название; в проекте есть открытые и закрытые баги
- **Ожидаемый результат:** на карточке указаны название и количество открытых багов; закрытые баги не учитываются в счётчике открытых

### TC-04-PROJ-02-SUCCESS_CARD_OPEN_BUGS_COUNT_ZERO

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Отображение количества открытых багов при их отсутствии
- **Входные данные:** проект имеет название; открытых багов нет
- **Ожидаемый результат:** на карточке указаны название и количество открытых багов, равное 0

### TC-05-PROJ-02-SUCCESS_CLICK_CARD_NAVIGATES_TO_PROJECT

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Переход на страницу проекта по клику на карточку
- **Входные данные:** пользователь состоит в проекте; проект отображается в списке
- **Ожидаемый результат:** по клику на карточку выполняется переход на страницу соответствующего проекта

### TC-06-PROJ-02-SUCCESS_EMPTY_PROJECT_LIST

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Отображение списка проектов при отсутствии участия в проектах
- **Входные данные:** пользователь не состоит ни в одном проекте
- **Ожидаемый результат:** на главной странице не отображаются проекты; система не показывает проекты других пользователей

## PROJ-03 — Добавленный участник в проект

### TC-01-PROJ-03-SUCCESS_ADD_EXISTING_USER_WITH_ROLE

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Добавление существующего пользователя в проект с выбранной ролью
- **Входные данные:** на странице проекта введён логин существующего пользователя; выбрана роль; действие выполняет Администратор проекта
- **Ожидаемый результат:** пользователь добавлен в проект; участник отображается в составе команды проекта с указанной ролью

### TC-02-PROJ-03-FAIL_NON_EXISTING_LOGIN

- **Тип:** FAIL (негативный)
- **Проверка:** Добавление пользователя с несуществующим логином
- **Входные данные:** введён логин, которого нет в системе; выбрана роль
- **Ожидаемый результат:** система корректно обрабатывает ошибку — отображается сообщение «Пользователь не найден»; участник не добавляется

### TC-03-PROJ-03-FAIL_EMPTY_LOGIN

- **Тип:** FAIL (негативный)
- **Проверка:** Обязательность поля «логин» при добавлении участника
- **Входные данные:** логин — пустой; выбрана роль
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение об ошибке обязательности логина; участник не добавляется

### TC-04-PROJ-03-FAIL_ROLE_NOT_SELECTED

- **Тип:** FAIL (негативный)
- **Проверка:** Обязательность выбора роли при добавлении участника
- **Входные данные:** введён логин существующего пользователя; роль не выбрана
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение об ошибке выбора роли; участник не добавляется

### TC-05-PROJ-03-FAIL_USER_ALREADY_IN_PROJECT

- **Тип:** FAIL (негативный)
- **Проверка:** Повторное добавление пользователя, уже состоящего в проекте
- **Входные данные:** введён логин пользователя, который уже является участником проекта; выбрана роль
- **Ожидаемый результат:** система корректно обрабатывает ошибку — сообщение о том, что пользователь уже состоит в проекте; дублирование участника не выполняется

### TC-06-PROJ-03-SUCCESS_NEW_PARTICIPANT_SEES_PROJECT

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Отображение проекта у добавленного участника
- **Входные данные:** существующий пользователь добавлен в проект; пользователь авторизуется
- **Ожидаемый результат:** новый участник видит этот проект в своём списке проектов

### TC-07-PROJ-03-SUCCESS_ADDED_USER_SEES_TEAM_AND_ROLE

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Отображение добавленного участника в составе команды
- **Входные данные:** существующий пользователь добавлен в проект с ролью; открыта страница проекта
- **Ожидаемый результат:** добавленный участник отображается в таблице участников; у него указаны логин и назначенная роль

## PROJ-05 — Функционал по удалению пользователя из проекта

### TC-01-PROJ-05-SUCCESS_ADMIN_DELETE_USER_WITH_CONFIRM

- **Тип:** SUCCESS (позитивный)
- **Проверка:** Удаление участника Администратором с подтверждением
- **Входные данные:** пользователь с ролью Администратора проекта; в проекте есть участник; выполнено подтверждение удаления
- **Ожидаемый результат:** после подтверждения участник исчез из списка команды проекта

### TC-02-PROJ-05-FAIL_NON_ADMIN_NO_DELETE_BUTTON

- **Тип:** FAIL (негативный)
- **Проверка:** Доступность кнопки удаления только Администратору проекта
- **Входные данные:** пользователь с ролью Разработчик или Тестировщик открыл состав команды
- **Ожидаемый результат:** кнопка удаления недоступна; удаление участника невозможно

### TC-03-PROJ-05-FAIL_NON_ADMIN_DELETE_DIRECT_ACTION

- **Тип:** FAIL (негативный)
- **Проверка:** Попытка удаления участника пользователем без прав Администратора
- **Входные данные:** пользователь с ролью Разработчик или Тестировщик пытается выполнить удаление участника
- **Ожидаемый результат:** система корректно обрабатывает ошибку — действие запрещено; участник не удаляется

### TC-04-PROJ-05-FAIL_CANCEL_DELETE_CONFIRMATION

- **Тип:** FAIL (негативный)
- **Проверка:** Отмена подтверждения удаления участника
- **Входные данные:** Администратор инициировал удаление участника и отменил подтверждение
- **Ожидаемый результат:** участник остаётся в списке команды; проект остаётся доступен участнику

### TC-05-PROJ-05-SUCCESS_REMOVED_USER_NO_LONGER_SEES_PROJECT

- **Тип:** SUCCESS (позитивный)

# E2E-тесты

## E2E-01 — Сценарий администратора проекта

### TC-01-E2E-01-ADMIN_FULL_FLOW

- **Тип:** E2E (позитивный)
- **Предусловия:** в системе существует пользователь; в проекте есть дефолтные справочники; существуют пользователи для добавления
- **Шаги:**
    1. Пользователь авторизуется.
    2. Создаёт проект.
    3. Удаляет все дефолтные справочники со всех категорий (только неиспользуемые).
    4. Создаёт по два справочника в каждой категории (Статус, Приоритет, Серьёзность).
    5. Добавляет пользователя в проект.
- **Ожидаемый результат:** пользователь авторизован; проект создан и отображается в списке; создатель — Администратор проекта; неиспользуемые дефолтные справочники удалены; создано по два элемента в каждой категории; добавленный участник отображается в составе команды с указанной ролью и видит проект в своём списке.

### TC-02-E2E-01-ADMIN_USED_DICTIONARY_NOT_DELETED

- **Тип:** E2E (негативный/граничный)
- **Предусловия:** в проекте есть справочник, используемый в баге
- **Шаги:**
    1. Пользователь авторизуется.
    2. Открывает проект и раздел справочников.
    3. Пытается удалить используемый элемент справочника.
- **Ожидаемый результат:** кнопка удаления неактивна; элемент не удаляется; мешающие связи не нарушаются.

## E2E-02 — Сценарий участника проекта

### TC-01-E2E-02-PARTICIPANT_FLOW

- **Тип:** E2E (позитивный)
- **Предусловия:** существует пользователь-участник проекта; пользователь состоит в проекте; в проекте настроены справочники
- **Шаги:**
    1. Пользователь авторизуется.
    2. Выбирает доступный проект из списка.
    3. Заполняет баг-репорт (заголовок, описание, приоритет, серьёзность, статус, шаги воспроизведения).
    4. Добавляет пользовательскую метрику и её значение.
- **Ожидаемый результат:** пользователь авторизован; выбран доступный проект; баг создан и появился в списке багов проекта; в истории бага есть запись о создании; пользовательская метрика создана; значение метрики сохранено с зафиксированным временем ввода; метрика отображается в разделе аналитики.

## E2E-03 — Сценарий участника проекта, закрывающего баг

### TC-01-E2E-03-PARTICIPANT_CLOSE_BUG_FLOW

- **Тип:** E2E (позитивный)
- **Предусловия:** существует пользователь-участник проекта; в проекте есть баг в статусе, допускающем переход в «Закрыта»; баг не закрыт
- **Шаги:**
    1. Пользователь авторизуется.
    2. Выбирает доступный проект из списка.

- **Ожидаемый результат:** пользователь авторизован; выбран доступный проект; статус бага изменён на «Закрыта»; в истории изменений появилась запись о смене статуса с датой и автором; данные дашборда и отчёта учитывают закрытый баг (виджет «Открытые баги» уменьшился, «Закрытые за неделю» увеличился).
