# Принятые проектные решения (QMS)

Документ для пояснительной записки: перечень принятых решений и их обоснований.

## 1. Стек и архитектура
- Backend: Laravel 13 (PHP 8.3+), PostgreSQL. Frontend: React 19 + TypeScript + MUI + React Query. Тесты: Pest (backend), Vitest (frontend), Playwright + Python (e2e).
- Слоистая архитектура: **Controller → Service → Repository**.
  - Контроллеры — только HTTP: валидация (FormRequest), авторизация (Policy/Gate), вызов сервиса, JSON-ответ.
  - Сервисы — бизнес-правила, транзакции, доменные ошибки.
  - Репозитории — доступ к данным (Eloquent), только через интерфейсы.
- Интерфейсы репозиториев + Eloquent-реализации; биндинги в `RepositoryServiceProvider`.
- Доменные ошибки: `DomainException` (+ HTTP-статус) → единый JSON `{message}` (обработчик в `bootstrap/app.php`).

## 2. Аутентификация и доступ
- Sanctum в режиме stateful SPA (сессии, CSRF): регистрация, вход, выход, `/me`.
- **Изменённое требование:** после успешной регистрации — переход на **главную** (не на форму входа). Отражено в `PROJECT_CONTEXT.md` и тестах.
- Роли проекта — через пивот `project_user` (`admin`/`developer`/`tester`) + `ProjectPolicy` (view/manageMembers/manageDictionaries/manageMetrics/delete) и `BugPolicy` (view/update — любой участник проекта).
- `spatie/laravel-permission` не используется и удалён (роли проектные, а не глобальные).

## 3. Справочники
- Дефолтные при создании проекта: **6 статусов** (мужской род: «Новый», «Назначен», «В работе», «Исправлен», «Переоткрыт», «Закрыт»), **4 приоритета** (low/normal/major/critical), **5 серьёзностей** (Blocker…Trivial).
- Флаг **`is_closed`** у статусов вместо сравнения по названию (миграция переименовывает статусы в существующих БД и проставляет флаг) — переименование в UI не ломает логику закрытия.
- Лимит **30** элементов на тип (валидация). Дефолтный статус удалить нельзя; используемый в багах — нельзя.
- Управление справочниками — только админ; чтение для форм/фильтров — всем участникам через `GET /projects/{project}/meta`.

## 4. Баг-репорты и история изменений
- Поля: заголовок, описание, приоритет, серьёзность, статус, исполнитель, шаги воспроизведения (описание и шаги — обязательные).
- История — **собственная таблица `bug_histories`** (+ `BugHistoryRepositoryInterface`); действия: `created/updated/status_changed/assignee_assigned`.
- `closed_at` управляется флагом `is_closed` статуса (используется в DASH и REPT).
- Фильтры/поиск: `search` (частичное совпадение по заголовку) + статус/приоритет/серьёзность/исполнитель, комбинируются; кнопка «Сбросить всё».

## 5. Метрики
- Типы: `numeric` и `categorical` (со списком `options`). Значения на багах с фиксацией `recorded_at`; уникально (metric_id, bug_id) — повторный ввод обновляет значение и время.
- Управление метриками — админ; ввод значений и аналитика — участники проекта.
- Аналитика: числовые показатели (avg/min/max/sum), распределение категориальных, разрез по статусам.
- UI: **график на каждую метрику** (числовая → среднее по статусам; категориальная → распределение значений).

## 6. Отчёты
- Показатели: всего багов (созданные за период), закрыто (закрытые за период), процент закрытых, среднее время жизни в часах = Σ(closed_at − created_at по закрытым за период) / кол-во закрытых; **незакрытые не учитываются**.
- Периоды: день / неделя / месяц.

## 7. Пагинация и лимиты
- Проекты и баги — Laravel-пагинатор с `?page=` и `?per_page ∈ {30, 50, 100}` (по умолчанию 30). UI — MUI `Pagination` + выбор размера страницы.
- Метрики — без лимитов и пагинации. Справочники — лимит 30 элементов на тип (см. §3).

## 8. Фронтенд-UI
- MUI + React Query; состояние страниц локальное (диалоги/фильтры).
- Закрытые дефекты: кнопки «← Назад к проекту» на страницах багов, дашборда и метрик; кликабельна **вся строка** бага (селекты быстрых действий не «проваливают» клик в строку).
- Описание проекта ограничено **500** символами (серверная валидация `max:500` + `maxLength` в UI).
- Локаторы ориентированы на MUI-роли/label (совместимы с интеграционными тестами).

## 9. Данные для демонстрации
- `DemoSeeder`: учётные записи `admin` / `developer` / `tester` / `user` (пароль `password123`), 2 проекта, по 15 багов с историей и комментариями, метрики со значениями; часть багов закрыта в пределах недели (для DASH/REPT). Сидер идемпотентен.
- Запуск: `php artisan migrate:fresh --seed` (очищает БД).

## 10. Тестирование
- Backend (Pest): Unit — сервисы на моках репозиториев и исключения; Feature — эндпоинты, репозитории, сидер, экспорт. Порог покрытия в CI — **80%**.
- Frontend (Vitest): пороги 80% (statements/branches/functions/lines) в `vitest.config.ts`; фактические значения ≈ 92 / 83 / 86 / 92.
- Локально покрытие бэкенда не измеряется (нет `xdebug`/`pcov`), измеряется в CI (там `xdebug`).
- E2E (Playwright + Python): page-objects конкретизированы; джоб в CI помечен `continue-on-error` (не блокирует сборку).

## 11. Инфраструктура и CI
- Docker: `php:8.4-fpm` (расширения: pdo_pgsql, mbstring, exif, pcntl, bcmath, gd, **zip, dom, simplexml, xml, xmlreader, xmlwriter**), nginx, PostgreSQL 15, фронтенд-nginx. Entrypoint: `composer install` при неполном `vendor` → `.env`/APP_KEY → пакеты → ожидание БД → миграции.
- Excel: `maatwebsite/excel ^4.0` (v1.1 несовместим с Laravel 13). Отчёт — **2 листа**: «Сводка» и «По статусам» (+ свойства документа).
- CI: backend (Pint + Pest + coverage ≥80%), frontend (ESLint + Prettier-check + tsc + Vitest + build), integration (Playwright, non-blocking), SonarCloud.
- Исправления инфраструктуры: добавлены отсутствующие PHP-расширения (требование `phpspreadsheet`), убраны маскирующие ошибки `|| true` в `Dockerfile`, усилен guard в `entrypoint.sh`.
